# APL-ANDROID-MANAGED-REFRESH-ROLLBACK
- M1: Only newly imported profiles explicitly assigned to a source ID may be managed. Never adopt legacy or manually added profiles by endpoint match. Manual edit detaches ownership; source deletion must preserve profiles and detach ownership.
- M2: Offline planner, exact baseline and source identity, bounded 200 source records and 2048 existing profiles. Same normalized endpoint (type, host, port, username) retains ID; name/password changes reviewed; absent owned rows proposed for removal; collisions with other sources/manual profiles skipped or rejected. Conflicting duplicate incoming rows reject entire update. Empty input never deletes all. Protected active/primary/last-auto/current selection cannot be changed or deleted. No network or automatic connection in planner.
- M3: User-visible additions, updates and removals; no secrets in summary. Explicit single-use approval while disconnected and foreground; expires after 5 minutes; compare exact current profile metadata, ownership, encrypted credential revision, selection and source at commit. Cancel on lifecycle changes.
- M4: One bounded, synchronous transaction for profile fields, encrypted credentials, ownership and rollback journal; previous configuration retained encrypted, not proven working until separately tested. Rollback is explicit and stale-state guarded; no overwrite of subsequent edits or unrelated profiles. Missing key/corruption/failure fail closed; real device fault injection required. No background polling or production release.
