# APL-ANDROID-QR-SHARE-20261126
- S1: Share action only from an already consented QR display, with a second explicit confirmation that the receiving app can retain plaintext credentials. No automatic sharing, clipboard, public storage or network requests by APL.
- S2: In-memory PNG only (max 1024x1024 and 1 MiB), random opaque content URI, non-exported provider with path-specific temporary read grant, no writes/listing, seekable read-only proxy descriptor with expiry rechecked for each provider callback. One active payload for 5 minutes; replace/revoke old grants; process death or expiry fails closed. Bytes cleared on invalidation where practical. Receiving app may retain a copy; expiry cannot revoke copied data or bytes already cached by the OS or recipient.
- S3: System ACTION_SEND image/png, chooser, ClipData + EXTRA_STREAM, no credential text, filename or subject. Do not persist state or real credentials. Existing secure display closes on pause; share payload survives only its bounded lifetime, intentionally independent of display dismissal.
- S4: Synthetic payload lifecycle tests, source boundary tests and exact-head CI; real chooser/recipient transfer/expiry separately on Android device. No production release.
