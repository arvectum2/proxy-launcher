# iOS 0.3.0 VLESS/REALITY synthetic TLS first-record diagnostics (24 November 2026)

Purpose: distinguish a TCP connection carrying zero bytes from a partial/complete initial TLS handshake record, without collecting payload, SNI, peer credentials, device addresses or profile fields. This is an isolated synthetic private-LAN peer test script, **not** a production PacketTunnel behaviour change.

Evidence before this change (23 November): actual signed iPhone r15 direct SOCKS greeting/CONNECT succeeded but independent HTTP receipt failed (7 relay TCP connections; 15,889 client bytes, 16,835 server bytes, 0 HTTP receipts). Signed iPhone r19 fp=firefox had 7 relay TCP connections but 0 client bytes, 0 server bytes and 0 HTTP receipts. Identical-version pinned Mac Xray fp=firefox r17 delivered HTTP receipt with a complete working positive control. No iPhone VLESS acceptance claimed.

Added `TLSFirstRecordMeter` to `mobile/ios/Tools/nativeqa_vless_tcp4_peer.py`: per physical connection record only total client bytes, bounded TLS record-header classification, declared first-record length, and whether the first record bytes were all received. It retains exactly five initial bytes in memory (TLS record header), never the handshake body and never raw packet contents in the observation JSON. Maximum eight observed connection summaries. If no bytes arrive, the observation reads `clientBytes:0` and `tlsHeader:incomplete`; a valid TLS header does **not** itself prove a successful REALITY handshake or HTTP delivery.

The same synthetic peer now fails its own preflight if the local positive-control ClientHello was not received as a complete TLS record. This prevents calling physical diagnostics valid when the measuring relay is broken. Tests cover zero bytes, split TLS header/body, complete header, malformed input and avoidance of packet payload storage.

Verification on Mac mini: pinned `hostpeer-preflight` with freshly copied throwaway r19 fixture and no physical iPhone/Apple profile changes -> `NATIVELAB_VLESS_PEER_READY`, `TLS_METADATA_CONTROL=PASS`; all temporary 39879/39882/39883/39884 listeners stopped. Four dedicated Python tests passed; current iOS release preflight passed; 50 current iOS 0.2 release-contract Python tests passed; 435 Swift shared-core tests passed; git diff check clean. A blanket historical `test_ios_*.py` run is **not** green: 260 tests, 2 failures + 14 errors including obsolete `MARKETING_VERSION:0.2.0` expectations in the 0.3.0 source. Do not label that older aggregate green.

Next: use one controlled signed synthetic iOS test **only if permitted without changing the user's original profiles or Apple capabilities**, capturing the new `firstTLSRecords` field plus exact independent app-layer HTTP receipt and precise tunnel cleanup. Possible outcomes: 0 client bytes -> inspect Xray client dial/write and iOS bound interface; incomplete first TLS record -> investigate stalled ClientHello; complete first record without HTTP -> investigate REALITY handshake and application request with limited, non-credential metadata. No blind fingerprint retries, no enablement without verified HTTP receipt. No PR merge, App Store release, or CloudKit capability change performed.
