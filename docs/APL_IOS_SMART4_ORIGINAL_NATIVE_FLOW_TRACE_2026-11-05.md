# Smart Routing 4.0 — диагностика исходного native TCP-потока

Задача `APL-IOS-SMART4-ORIGINAL-FLOW-TRACE-20261105`, исходная ветка `main` от `f06a091d` (PR #345). 5 ноября 2026.

## Что проверяется

Реальная iOS-часть tun2proxy уже отправляет callback с **одним исходным native connection ID**, относящимся к захваченному из PacketTunnel TCP-сеансу (не к произвольно созданному QA-приложением сокету):

- `0` — принятое соединение через CONNECT-прокси; это **не** означает успешного обмена прикладными данными.
- `7` — исходный TCP-поток восстановлен после неуспешного подключения к прокси в экспериментальном scoped-direct сценарии.
- `8` и `9` — первые записанные направления прикладного потока (к серверу и от сервера) в native движке.
- `10` или `11` — IPv4/IPv6 адрес фактического физического direct-TCP-сокета в экспериментальном native транспорте.

Новый `SharedCore/Smart4OriginalFlowTrace.swift` не изменяет маршруты. Он сверяет native event 7, обе передачи 8/9 и ровно одно семейство адреса 10/11 **для одного и того же connection ID и идентичного проверенного имени**. Без полного набора подтверждений исходный поток считается неопределённым, события других соединений никогда не складываются в общее доказательство. Отдельное успешное соединение, DNS или IP-сходство не подтверждает исходный поток.

## Конфиденциальность и fail-closed

Диагностика принимает только фиксированные уже существующие QA-host aliases (`www.apple.com`, `www.apple.com.cn`, `ipv6.l.google.com`, `start.qa-example.test`), но не сохраняет эти строки: в оперативной памяти остаются только enum-alias, native ID, набор числовых событий и кратковременные метки времени. Не сохраняются URL, DNS, IP, TLS-данные, одноразовые токены, VPN-пароли или пользовательская история посещений.

Лимиты: максимум 32 потока, срок 60 секунд, сброс при старте/остановке; переполнение сохраняет `overflowed=true` до перезапуска. Конфликт двух имён на одном ID, два физических семейства, повтор события восстановления/первого payload, смена времени назад, отсутствующее серверное направление и бездоказательный ID всегда исключают положительную классификацию. В TelemetryStore пишется максимум одно обезличенное событие об обнаруженном same-flow обмене **и только при существующем явно включённом DEBUG `labScopedDirect`**. `externalEgressVerified` всегда `false`.

## Граница безопасности

Это **первый слой** корреляции «исходный поток → решение native engine», а не последний слой «исходный поток → независимый серверный witness». Приложение на рабочем iPhone 0.1.41 не заменялось; Debug/Release routing, NE excludedRoutes, профили, Keychain, Apple Review и недоказанный PR #314 не изменялись. Production DIRECT не включать.

Для закрытия аппаратного gate 2b.2 нужно на отдельном подписанном тестовом PacketTunnel с безопасным backup/rollback провести настоящие сетевые пробы: идентификатор исходного потока и его независимый одноразовый token должны сходиться на двух внешних серверах DIRECT/PROXY в пределах TTL; проверить одноимённые shared-CDN IP, IPv4/IPv6, UDP/QUIC, смену сети и отзыв разрешений. Один native callback без независимого серверного свидетельства никогда не является доказательством внешнего маршрута.

## Проверки

- 12 Swift-тестов чистого in-memory native trace: восстановление исходного соединения, оба направления payload, независимость ID, конфликт exact-host, отсутствие семейства, повтор, лимит и TTL.
- 3 Python-контрактных теста: Rust patch сохраняет один original ID, DEBUG lab guard, отсутствие включения production route и сохранения личных данных.
- **Swift Core 193/193 PASS** (12 новых тестов), **iOS Python 202 (1 skipped) PASS** (3 новых contract tests); **ARM64 unsigned iPhoneOS App+PacketTunnel BUILD PASS** и **ARM64 iOS Simulator App+PacketTunnel BUILD PASS**. Первые сборки с новой рабочей копии не нашли игнорируемый Git локальный tun2proxy xcframework; после восстановления того же проверенного бинарника из локального build-cache обе сборки прошли, slice SHA256 идентичны источнику. Предсуществующие Swift 6 Sendable warnings не изменялись.
