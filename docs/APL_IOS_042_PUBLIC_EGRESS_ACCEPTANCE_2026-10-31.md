# APL iOS 0.1.42 (47): независимая проверка внешнего IP на физическом iPhone

**Дата:** 31 октября 2026 г. **Устройство:** iPhone 13 с iOS 27.2, подключение к Mac mini по Wi-Fi / CoreDevice. **Исходный репозиторий:** `arvectum2/proxy-launcher`, `main` после PR #291 (`a25e7b2e`). **Сборка:** подписанная `Debug-iphoneos` 0.1.42 (47) с единственным opt-in флагом `APL_RUN_EXPLICIT_VPN_QA`. Apple App Store Connect и отправленная на ревью 0.1.41 (46) не затронуты.

## Цель и методика

Отличить «интернет работает при включённом системном VPN» от фактической смены публичного IP. Один и тот же независимый XCTest-процесс на iPhone запрашивает внешний IP у **двух разных HTTPS-источников**:

- `https://api.ipify.org`
- `https://www.cloudflare.com/cdn-cgi/trace` (поле `ip=`)

Статические и кэшированные HTTP-ответы отключены (`URLSessionConfiguration.ephemeral`, `reloadIgnoringLocalCacheData`). Перед включением APL оба адреса считываются дважды для подтверждения стабильной исходной сети. После активации настоящего `NetworkExtension.PacketTunnel` оба источника запрашиваются заново, затем APL штатно отключается, и проверяется восстановление исходного IP с допуском на задержку перестроения маршрутов iOS.

**Приватность:** точные публичные IP, учётные данные, адреса и названия пользовательских прокси не записываются в тестовые журналы, GitHub или отчёт. Доступны только булевы результаты сравнений по каждому поставщику.

## Фактические результаты и повторные попытки

| Запуск | Наблюдение | Результат |
| --- | --- | --- |
| Предварительная физическая проверка | APL `Отключено`, профили на месте, iPhone доступен | **PASS** |
| Первая попытка | Оба HTTPS-сервиса доступны до подключения, но APL не перешёл в `Подключено` за 9 секунд. До замера при VPN дело не дошло | **FAIL** — неподтверждённая маршрутизация, без утверждений об IP |
| Независимая проверка после первой попытки | APL снова `Отключено`, профили сохранены, CoreDevice доступен | **PASS** |
| Вторая попытка | При активном VPN **2 из 2** источников показали смену IP. После немедленного отключения исходный адрес вернулся только у **1 из 2** | **FAIL** по строгому критерию немедленного восстановления; вероятная задержка сети |
| Независимая проверка после второй попытки | APL `Отключено`, профили на месте, iPhone доступен | **PASS** |
| **Финальный запуск** | Сеть до VPN стабильна (два последовательных опроса, 2/2 совпадений). При APL `Подключено` — **2/2 публичных IP изменились**. После явного отключения: первый опрос вернул исходный IP у 1/2, **второй опрос — у 2/2** | **PASS**, физический XCUITest **26,986 с, 0 failures, 0 skips** |
| **Независимая финальная проверка** | `APL_PHYSICAL_VPN_READONLY state=Отключено hasProfiles=true`; устройство доступно, установленная версия **0.1.42 (47)** | **PASS** |

Именно отсроченное восстановление одного IP объяснило второй неудачный тест; финальный тест допускает до четырёх *только read-only* замеров после подтверждённого отключения VPN. Новый туннель при этих замерах не включается.

## Безопасность включения

Тест `PhysicalProxyEgressUITests` компилируется **только** с `APL_RUN_EXPLICIT_VPN_QA`; при запуске на симуляторе автоматически пропускается без переключения VPN. На реальном устройстве дополнительный аргумент `-aplEphemeralTunnelQA` включает два отдельных защитных механизма отладочной сборки: запрос отключения приложения через **20 секунд** и аварийную остановку Packet Tunnel через **25 секунд**. В каждом тесте присутствует `defer` со штатным нажатием «Отключить» при ошибке. После всех попыток состояние APL было независимо подтверждено как OFF. Никакие сохранённые прокси-профили не редактировались или удалялись.

## Границы доказательств

**Доказано:** на том же физическом iPhone оба независимых публичных HTTPS-сервиса наблюдают смену IP при активном APL Packet Tunnel и возвращаются к исходным адресам после его отключения; это сильное независимое подтверждение выхода трафика через иной сетевой маршрут. Прямой HTTPS через APL также был ранее проверен в PR #291.

**Не доказано отдельно:** имя/идентичность конкретного выбранного upstream-прокси и число байт, прошедших через `tun2proxy`; восстановление *стороннего* Tailscale/Amnezia VPN; полнота исключений, IPv6/QUIC/DoH в других приложениях; оптическое считывание QR с реального другого экрана. Для полноценной дальнейшей приёмки можно добавить агрегированные счётчики внутри Packet Tunnel и сравнить их до/после реальных запросов, не выгружая приватные прокси-адреса.

**Важно:** первые две неудачные попытки в отчёте сохранены, а не замаскированы успешным последним запуском. Тест не предназначен для регулярного CI, поскольку меняет реальный системный VPN. Повторять без отдельной необходимости не следует.
