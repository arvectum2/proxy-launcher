# APL iOS 0.2 — зашифрованные резервные копии профилей

Статус: исходный код и симулятор проверены, физический iPhone/Files round-trip пока не принят. Реализация: `mobile/ios/SharedCore/ProfileBackup.swift`, `ProfileBackupRestorePlan.swift`, `App/ProfileBackupView.swift`.

## Сценарий пользователя

На вкладке «Профили» → «Резервные копии» пользователь задаёт парольную фразу (минимум 12 символов), подтверждает её и выбирает место сохранения системным диалогом «Файлы». Создаётся только зашифрованный файл `.aplbackup`. Для восстановления выбирают файл и вводят исходную фразу. Забытый пароль расшифровать силами Arvectum нельзя. Следует хранить копию и парольную фразу раздельно, вне постороннего доступа.

## Формат v1

Файл — JSON-конверт с полями `format = arvectum.apl.encrypted-profiles`, `version = 1`, `kdf = PBKDF2-HMAC-SHA256`, `iterations = 210000`, `salt` и `ciphertext`. Двоичные поля кодируются Base64. Соль — 16 криптографически случайных байтов. Ключ — 32 байта по PBKDF2-HMAC-SHA256, затем шифрование CryptoKit AES-256-GCM со случайным nonce; `ciphertext` содержит комбинированный nonce, шифртекст и тег аутентификации.

**Все серверы, имена, логины и пароли находятся только внутри AEAD-шифртекста.** Расшифрованный JSON содержит до 200 пар `ProxyProfile` и пароль Keychain, ID избранных и группы. Не экспортируются активная сессия VPN, правила исключений, cookies, рекламные идентификаторы, настройки рекламы или история диагностики. Пароль копии не сохраняется в UserDefaults или Keychain и не отправляется на сервер.

При открытии отвергаются неверные `format`, версия, KDF, число итераций, размер соли/шифртекста или файл более 1 MiB **до** ресурсоёмкой PBKDF2. Затем AES-GCM проверяет целостность **до** декодирования профилей. Формат не предусматривает незашифрованного fallback. Неизвестную будущую версию нужно мигрировать явно, а не угадывать.

## Безопасность восстановления

- Формируется полный план до первой мутации: проверка профилей и общего лимита 200, дедупликация по типу/хосту/порту/логину, генерация новых UUID для импортируемых серверов.
- Существующие UUID, Keychain-записи и активный профиль никогда не перезаписываются из файла. Группы/избранное применяются только к вновь импортированным UUID.
- Если сохранение нового профиля прерывается, созданные записи удаляются с best-effort откатом. При неполном откате пользователь получает отдельное предупреждение и должен проверить список.
- Импорт запрещён при подключённом или подключающемся VPN. Экспорт разрешён, поскольку это только чтение локальных данных.

## Проверки и ограничения

Адреса/секреты не встречаются в сериализованном конверте; проверены симметричный round-trip, неверная фраза, изменение файла, случайные соль/nonce, вредоносное число PBKDF2 итераций, дубликаты UUID, лимит 200 и сохранность старых записей. В iOS Simulator прошли появление экрана и запрет создания копии без парольной фразы, а также ARM64 Debug/Release сборки. Сам диалог Files с настоящим сохранением и восстановление Keychain между установками требуется проверить на реальном iPhone перед TestFlight/App Review. Никакой публикации в Apple этот документ не разрешает.
