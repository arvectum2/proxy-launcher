# APL-REG-001D — технические средства хранения, сборки, выпуска и распространения

Регистрационный экземпляр: **Arvectum Proxy Launcher 0.2.9**

Документ подготовлен для требований пункта 11 «ж» и «з» Правил ведения реестра. Финальная подаваемая редакция должна описывать **фактический российский production perimeter**, подтверждённый APL-REG-001B evidence. Ниже отдельно указаны уже доказанные публичные факты и незакрытый filing target.

## 1. Хранение исходного текста

Публичный canonical repository проекта: `https://github.com/arvectum2/proxy-launcher`.

Для соответствия пункту 5 «и» одного публичного GitHub недостаточно: технические средства хранения исходного текста, используемые как filing-grade perimeter, должны фактически находиться на территории Российской Федерации. Целевая схема и формат evidence определены в `APL-REG-001B_SOVEREIGN_LIFECYCLE.md`.

Перед подачей в эту секцию должны быть внесены без секретов:

- наименование/роль российского authoritative source storage;
- оператор и основание контроля;
- физическая территория размещения — Российская Федерация;
- идентификатор exact source revision для `v0.2.9`;
- способ резервного хранения/восстановления;
- audit evidence доступа/синхронизации, достаточный для подтверждения реального контура.

## 2. Хранение объектного кода

Публичный `v0.2.9` выпускает Setup/portable для Windows, DEB для Astra Linux, RPM для RED ОС и `SHA256SUMS.txt`.

Для filing-grade схемы authoritative object-code storage должен находиться в РФ. GitHub Releases может оставаться публичным вторичным каналом, но сам по себе не подтверждает п. 5 «и». Российское зеркало GitVerse существует, однако до подачи необходимо подтвердить фактическую роль, операторский контроль и соответствие требованию размещения.

## 3. Компиляция исходного текста

Репозиторий содержит воспроизводимые build primitives:

- Windows clean-build pipeline `tools/clean_build_windows.ps1` с возможностью offline hash-locked wheelhouse;
- Linux CI/build pipeline, формирующий DEB/RPM artifacts;
- тесты и release policy, связывающие source revision с artifacts/hashes.

Публичная CI-конфигурация не доказывает территорию фактического build host. Для п. 5 «и» exact filing release должен быть собран либо воспроизводимо подтверждён на технических средствах компиляции, физически находящихся в РФ. APL-REG-001B предусматривает фиксацию build host, offline inputs, source commit и artifact SHA-256.

## 4. Активация и лицензионные ключи

Текущая публичная редакция распространяется по MIT License и **не использует** обязательную активацию, лицензионный сервер или систему управления ключами. Для этих функций технические средства отсутствуют как неприменимые к текущей модели.

Если коммерческая модель изменится до подачи, секция должна быть пересмотрена.

## 5. Выпуск и распространение

Текущие публичные каналы:

- canonical GitHub release: `https://github.com/arvectum2/proxy-launcher/releases/tag/v0.2.9`;
- независимое российское зеркало: `https://gitverse.ru/arvectum/proxy-launcher/releases`.

Для выполнения п. 5 «к» технические средства, используемые для filing-grade выпуска/распространения, должны находиться в РФ и контролироваться российскими организациями либо гражданами РФ. Перед подачей необходимо зафиксировать реальный authoritative Russian distribution path и доказательство его контроля. GitHub после этого может оставаться вторичным публичным каналом.

## 6. Контроль целостности

Release set содержит `SHA256SUMS.txt`. Filing evidence должен связать:

`exact source revision → российский build record → exact artifact SHA-256 → authoritative Russian artifact storage/distribution → публичный mirror bytes`.

Любое несовпадение hash должно считаться fail-closed и не приниматься как тот же регистрационный экземпляр.

## 7. Статус

**BLOCKED FOR FILING EVIDENCE** до физического выполнения APL-REG-001B. Этот статус относится не к отсутствию build tooling, а к отсутствию в публичном репозитории проверенного факта, что используемые filing-grade storage/build/release technical means реально находятся в РФ и контролируются требуемым образом.
