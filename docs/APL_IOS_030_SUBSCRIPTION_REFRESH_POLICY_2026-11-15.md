# Step 3 — subscription refresh review (offline contract)

The existing manual saved HTTPS subscription fetch, preview and additive import remain unchanged. `ProxySubscriptionRefreshReview` prepares the next stage without activating it. It is a MainActor in-memory policy; it is not a scheduler, a download implementation, a persisted setting or a production UI.

- Explicit opt-in for an exact saved source ID and revision allows a foreground due hint after one hour, one day or one week. Opt-in does not grant network access or renew itself after relaunch. Every actual request still requires a foreground user action, independently of the hint. Opt-out invalidates work. No automatic requests, retries or profile changes.
- At most one request or review is outstanding. The caller must provide the live source revision independently, and cancel on dismissal/background/source removal; responses are bounded to 60 seconds using monotonic uptime and the existing 256 KB/200-row parser. The review expires after five minutes. Unsupported and conflicting credential rows fail closed.
- The metadata-only summary counts received, existing, repeated and new candidates. Duplicate endpoint identities use structured protocol/host/port/username fields. Existing profiles are skipped even when incoming credentials differ; the contract does not read existing Keychain passwords, infer credential rotations, delete disappeared rows, or change the active selection. No provider association is persisted.
- Explicit single-use confirmation requires the exact source revision, foreground state and unchanged profile metadata snapshot (bounded to 2048 existing entries). Returns only additive candidates to a future transaction caller, which must independently recheck the current source and snapshot at commit. Credentials exist in temporary memory only; no guaranteed memory zeroization. The caller's source revision authority, persistence, transaction atomicity, UI and actual network lifecycle are not implemented by this contract.

Tests: four new Swift cases covering opt-in/due hints, foreground/manual consent, additive deduplication, conflicting rows, cancellation, late response, source/snapshot drift, expiry and replay. Full Swift379/379; Python420/420 +1527 subtests, including explicit source-contract check that the new policy is not invoked by production App/PacketTunnel/Shared. No live supplier URL/token access or request, no background task registration. The future optional subscription refresh feature is not a mandatory release gate for the currently agreed manual flow.
