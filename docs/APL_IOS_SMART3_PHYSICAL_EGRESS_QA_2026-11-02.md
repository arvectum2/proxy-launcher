# APL iOS 0.2.0 Smart Exclusions 3.0 — аппаратная A/B-приёмка

**Дата:** 02.11.2026. **Устройство:** спаренный физический iPhone 13 (iOS 27.2), Mac mini, Xcode 27.1, Debug iOS 0.2.0 (48), отдельный временный Python HTTP CONNECT proxy в LAN с автоматическим прекращением. **Релиз 0.2.0 в App Store не отправлялся.** Существующий пользовательский прокси/пароль не задействован, тестовый профиль не сохранялся. Перед тестами сделана локальная резервная копия App Group preferences и подписанной исходной `.app`.

## Что протестировано на железе

1. **Рекомендации, без воздействия на маршруты:** `testAdaptiveConnectionSuggestionRequiresManualConsent` сначала не сработал — тестовая инъекция была `#if DEBUG && targetEnvironment(simulator)` и не действовала на физическом устройстве. Исправлено: имитация только `#if DEBUG` и **в памяти `AppViewModel`, без записи в App Group**. Повторный реальный XCUITest на iPhone **PASS (15,551 с)**: кандидат виден, IP-wide warning показан, неподтверждённый домен не добавлен в исключения.
2. **Самостоятельный интерфейсно-ограниченный TLS:** `testPhysicalInterfaceScopedTLSConnectivity` использует настоящий `NWConnection` + `NWParameters.requiredInterfaceType = .wifi` и TLS с SNI; `www.apple.com` возвращает `tlsReadyViaWiFi`, XCUITest **PASS (0,184 с)**. Это доказывает работу API на физическом устройстве, **не** отдельный маршрут всего веб-трафика.
3. **Реальный Packet Tunnel и per-host Rust callback:** `testLiveVPTunnelPerHostCONNECTSignalWithAutoRollback`, временный макет HTTP CONNECT на Mac mini, 20-секундное отключение из APL и независимое ограничение 25 с в `PacketTunnelProvider`. Первая серия с `probe.qa-example.test` и `auth.qa-example.test`: **3 TCP CONNECT** в mock, **две уникальные TCP-сессии** `auth.qa-example.test` сохранены по цепочке `NEPacketTunnelProvider → tun2proxy VirtualDNS → C ABI SmartFlowEventCollector → ProfileStore.smart_route_evidence.v1`, прочие private prefs не считывались или не изменялись. XCUITest PASS, VPN отключён.
4. **A/B под активным VPN — разные пути для одного hostname:** финальный тест с реальными DNS-именами, специально обработанными **только на тестовом proxy**: `www.cloudflare.com:443` получил **один CONNECT 200** (healthy), `www.apple.com:443` — **два зависающих CONNECT**, каждый ограничен 12-секундным сроком. В тот же период отдельный `NWConnection` к `www.apple.com` с `requiredInterfaceType=.wifi` завершил TLS как `tlsReadyViaWiFi`. Mock proxy зафиксировал ровно **два** CONNECT к `www.apple.com` от тестовых app flows, то есть независимый TLS probe не использовал этот mock. Real-device XCUITest **PASS (26,306 с)**. В локальном App Group JSON после сессии обнаружена запись `www.apple.com` с **двумя уникальными session ID**, здоровый `www.cloudflare.com` не превращён в проблемный домен. Данные пользовательских аккаунтов/прокси не выгружались.
5. **Возврат после теста:** temporary mock server остановлен, Packet Tunnel process отсутствует, CoreDevice iPhone снова `available (paired)`. Оригинальная подписанная `.app` **0.2.0 (48)** восстановлена через `devicectl device install app` без удаления App Group/Keychain и с тем же bundle ID. Приватные настройки сохранены. Диагностические QA записи имеют короткое время актуальности 120 с и отбрасываются при следующей networkID-сессии.

## Реализовано в исходниках

- `App/AdaptiveDirectProbe.swift`: одноразовый проверяемый TLS handshake через `NWConnection` с required Wi-Fi/Cellular interface и серверным именем TLS, ограничение времени, нет cookie, авторизации, загрузки страниц, постоянного наблюдения. Возвращает только `tlsReadyViaWiFi`/`tlsReadyViaCellular`/`unavailable`. В `ExclusionsView` максимум три последних проблемных домена проверяются последовательно **при открытии экрана** (не непрерывно в фоне). UI честно показывает «маршрут не подтверждён». Запрет автоматического IP-wide обхода остаётся.
- Debug-only `Smart3PhysicalTrafficQA.swift` и `-aplSmart3LocalProxyQA` загружают **одноразовый профайл только внутри PacketTunnel** на конкретный лабораторный адрес LAN; `ProfileStore.save` для него **не вызывается**. После 20–25 секунд VPN принудительно отключается. **В Release код QA-инъекции отключён `#if DEBUG`**.
- `AdaptiveDirectProbePhysicalUITests` и `Smart3LiveTunnelPhysicalUITests` позволяют повторить физические тесты без реального платного прокси; в тесте намеренно не создаётся автоматический DIRECT-маршрут или новый серверный продукт.

## Почему iOS 0.2.0 по-прежнему под release gate

На железе подтверждено: `auth`-подобный домен может давать повторные proxy failures, а отдельный TLS socket имеет независимую живую Wi-Fi связь. **Но это не даёт iOS поддерживаемого способа автоматически направить все соединения Safari только к этому hostname напрямую.** По [Apple TN3120](https://developer.apple.com/documentation/technotes/tn3120-expected-use-cases-for-network-extension-packet-tunnel-providers) `NEPacketTunnelProvider` предназначен для туннельного соединения с удалённой сетью, не для selective forwarding на другой интерфейс. По [Routing your VPN network traffic](https://developer.apple.com/documentation/networkextension/routing-your-vpn-network-traffic) `excludedRoutes` у Packet Tunnel указывают **IP-подсети**, поэтому silent `/32` для `auth.example.com` раскрывает другие сайты на этом CDN IP. По [NEAppProxyProviderManager](https://developer.apple.com/documentation/networkextension/neappproxyprovidermanager) на iOS app-proxy требует MDM managed per-app VPN payload; consumer standalone приложение не может использовать его вместо обычного Packet Tunnel для любого Safari.

**Не утверждать DONE для Smart Exclusions 3.0:** нужны подтверждённый поддерживаемый платформой точный per-host direct routing, аппаратный shared-CDN-IP тест неизвестного второго hostname и окончательное решение владельца о допустимом iOS компромиссе. **Не отправлять 0.2.0 на публикацию автоматически.** Текущий безопасный fallback: самостоятельно находить и проверять подозрительные hosts, затем предложить user-consent bypass с явным предупреждением общего IP. В старых профилях сохранён прежний `SharedIPRouteGuard`, а не абсолютная гарантия, что неизвестных shared-IP соседей нет.
