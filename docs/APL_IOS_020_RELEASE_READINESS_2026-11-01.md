## 2. Риски перед выпуском

### Решение владельца по действующему релизу

Рекламная интеграция и текущие сведения в App Store Connect остаются **без изменений** по прямому решению владельца. Прежние обсуждения этого вопроса закрыты; не вводить дополнительных проверок и не поднимать тему повторно без нового запроса владельца.

### A. Полная приёмка системного Files picker — до TestFlight

- Формат криптографически проверен, но системное сохранение → открытие именно этого файла → расшифровка на устройстве требуется отдельным результатом. Запускается **только на disposable iPhone Simulator с synthetic `.invalid` прокси и паролем**, никогда на пользовательском iPhone с сохранёнными паролями; пользовательские секреты не копируются в QA.
- Проверить экспорт `.aplbackup`, затем импорт из системных «Файлов», пароль и дедупликацию, затем восстановление на новой пустой установке/контейнере, сохранность Keychain и отсутствие plaintext в файле.
- На выделенном симуляторе подписанная QA-сборка прошла до системного экрана «On My iPhone» → `Save` (кадры и отчёт в локальном закрытом QA-каталоге), но удалённый Apple File Provider не предоставил стабильный элемент кнопки Save через XCUITest. Кнопка самого APL создала зашифрованный документ и открыла системный диалог, однако **завершение сохранения, повторный выбор и восстановление не подтверждены**. Тест `EncryptedFilesRoundtripUITests` доступен только с отдельным `APL_RUN_EXPLICIT_FILES_QA`; он исключён из обычного CI, чтобы не создавать ложную регрессию.
- Приёмку Save→Files→Open→Decrypt завершить вручную на выделенном симуляторе или после разрешения XCTest на устройстве. До этого статус **НЕ ПРОВЕРЕН**, несмотря на успешную криптографическую Core-проверку.

### B. Реальный egress и failover — недостающие аппаратные сценарии

- `PhysicalProxyEgressUITests` проверяет стабильный baseline двумя сервисами `api.ipify.org` и Cloudflare trace, переключение egress при VPN ON и возвращение baseline при OFF; **сырой IP не записывается в лог**.
- `PhysicalVPNControlledUITests` уже провёл ограниченный HTTPS. После изменения Home тесты обновлены с чтения несуществующего текста «Отключено» на доступную кнопку «Подключиться».
- Для тестов XCTest на физическом iPhone система ранее попросила **код-пароль на разрешение UI Automation**. Не вводить/запрашивать пароль в чате; дальнейшая аппаратура требует разрешения пользователем непосредственно на устройстве. При повторной проверке подключения 01.11.2026 CoreDevice определил iPhone как **unavailable**, поэтому новая аппаратная проверка egress не запускалась. Физический failover требует двух доступных тестовых прокси и готовности временно менять VPN; без них нельзя заявлять PASS.
