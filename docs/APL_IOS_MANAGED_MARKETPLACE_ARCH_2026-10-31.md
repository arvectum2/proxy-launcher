# APL iOS — managed profiles и Marketplace: архитектура и границы

Дата: 31.10.2026. **Это техническая подготовка, НЕ запуск продаж, API, подписок или реальных поставщиков.** Старый ручной импорт остаётся доступен без аккаунта.

## Версия подписанного контракта

`ManagedProfileContract` — чистая модель, она ничего не загружает, не покупает и не записывает в Keychain. При подключении к будущему HTTPS клиенту подписант должен быть доверен **до** получения ответа. Сам HTTPS URL не даёт права принять неизвестный публичный ключ из того же ответа.

```json
{
  "version": 1,
  "keyId": "provider_2026",
  "payload": "<base64(JSON payload bytes)>",
  "signature": "<base64(Ed25519 signature of exact payload bytes)>"
}
```

Payload: `schemaVersion`, `issuer`, `revision`, `issuedAt`, `expiresAt`, `profiles`; каждый профиль: `id`, `name`, `host`, `port`, `type`, `credentialRef` (НЕ пароль и НЕ bearer token). Максимумы: оболочка 256 КБ, payload 128 КБ, 32 профиля, срок 30 дней. Требования: HTTPS-источник без userinfo/query/fragment, hostname вместо loopback/IP, совпадение issuer с источником, валидная подпись Ed25519, строгий перечень полей, уникальные ID, поддерживаемые только HTTP/HTTPS/SOCKS5 и монотонная ревизия.

Новые или исчезнувшие профили, смена `host`/`port`/`type` требуют подтверждения, даже если подпись верна. Старые ревизии и неизвестные поставщики отклоняются. Последняя известная исправная конфигурация может использоваться только пока не истёк её срок. Новые профили не включаются автоматически. Версия схемы 1 не обещает поддержку VLESS/Reality до появления реального движка.

## Будущий backend (только план)

| Endpoint | Функция | Безопасность |
| --- | --- | --- |
| `GET /v1/catalog` | Тарифы и доступность | Без клиентских секретов |
| `POST /v1/orders` | Идемпотентный заказ | Никакого доверия клиентскому `paid` |
| `GET /v1/orders/{id}` | Статус оплаты | Проверенный серверный webhook |
| `POST /v1/entitlements/{id}/bind` | Право на управляемый профиль | Одноразовая привязка |
| `GET /v1/managed/{id}/manifest` | Подписанный манифест | Key rotation, ETag, bounded HTTPS redirects |
| `POST /v1/credential-redemptions` | Секреты по разрешённому праву | Keychain, не UserDefaults/логи |
| `POST /v1/entitlements/{id}/revoke` | Отзыв | Подтверждение владельца, идемпотентность |

При будущем refresh: лимиты размера/времени, запрет cross-origin redirect по умолчанию, доверенный keyring с ротацией, транзакционное применение и rollback; expired entitlement не может молча подключаться. `credentialRef` должен быть только несекретным ID, получение реального секрета — отдельно по короткому авторизованному токену непосредственно в Keychain.

## Границы юридических/коммерческих решений

1. **Предмет продажи:** право использования ПО, доступ к прокси/транзиту, посредническая выдача чужой услуги или B2B-сопровождение. Нельзя считать, что смена наименования услуги автоматически исключает правовые ограничения.
2. **Оплата ₽ и App Store:** для цифровых функций/подписок внутри iOS исходно оценить требование StoreKit IAP (Apple 3.1.1), мультиплатформенный доступ (3.1.3(b)) и региональные правила для внешних ссылок. Не вставлять оплату на российском сайте/боте прямо в iOS как обход StoreKit. Отдельно анализировать Apple 5.4 VPN Apps и запрет продажи/передачи пользовательских данных VPN-приложениями.
3. **Инфраструктура и ПД:** определить владельца/поставщика RU ingress, зарубежных exit nodes, допустимость услуги и регион лицензирования, порядок обработки ПД по российскому праву, уведомление Роскомнадзора, место хранения базы и договоры с поставщиками. Не утверждать готовность РКН/лицензий без действительных подтверждений.
4. **Продуктовые решения:** тарифы, лимиты, возвраты, поддержка, страна доступности, право отзыва, ответственность за провайдера и биллинг. Их принимает владелец до production.

Официальные источники: [Apple App Review Guidelines 3.1, 5.1, 5.4](https://developer.apple.com/app-store/review/guidelines/), [обновление от 16.10.2026](https://developer.apple.com/news/?id=92th7e5i). Для российского регулирования требуется независимое юридическое заключение по фактической бизнес-модели.
