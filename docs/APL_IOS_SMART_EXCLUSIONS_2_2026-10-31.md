# Smart Exclusions 2.0 — iOS, 31 октября 2026

## Реализовано в source

- Добровольный WebKit-анализ, непостоянное хранилище, ограничения времени (18 с), HTML (512 КБ) и сетевых ресурсов (512).
- Локальный граф `сайт → точный дочерний домен → HTML/Network/оба → время наблюдения → решение`: максимум 24 связи на сайт, 32 сайта, TTL 7 дней. Повторное сканирование не превращает отклонённый домен в разрешённый.
- Подтверждение каждого домена, отзыв, удаление, очистка, Undo. Только одобренные дочерние хосты активного ручного исключения становятся правилами обхода. Нарушенные, устаревшие и неподтверждённые записи не участвуют в маршрутах.
- Независимые HTTPS-хосты отображаются отдельно; для ручного исключения необходимо предупреждение о разделяемых IP. Не одобряются автоматически.
- Совместимое хранение в App Group, прежние `site_exclusions` трактуются как ручные. Новые правила записываются после полной проверки; неудачное переподключение откатывает конфигурацию, повторное восстановление VPN обязательно пытается выполнить.
- Проверенный hardcoded `gosuslugi.ru → gu-st.ru` пока сохранён для совместимости, до физической проверки общего алгоритма.

## Где пока нет гарантий

Сегодняшний iOS Packet Tunnel использует реальные `NEIPv4/NEIPv6.excludedRoutes` и патч tun2proxy `--dns-bypass HOST=IP`. Маршрут по IP действует на *все* сайты с общим CDN IP; это не безопасная изоляция по домену. Смена DNS/CNAME/TTL требует переподключения для нового набора IP; старый активный туннель не умеет заменять правила без перезапуска. DoH, ECH, QUIC/HTTP3 и авторизованные ресурсы без наблюдаемой зависимости нельзя надёжно обнаружить.

**Phase C, следующий исследовательский этап:** версионированная точная политика DIRECT/PROXY на уровне каждого нового сетевого потока в tun2proxy, привязка DNS QNAME к виртуальному IP с TTL, физический egress без utun-петель, отказ в DIRECT при отсутствии уверенной атрибуции; отдельная обработка IPv6 и UDP. Сохранение существующих соединений при смене политики, таймауты и аварийный откат — обязательны. Ни компиляция, ни успешный DNS-тест не доказывают реального обхода. Перед включением нужен аппаратный iOS/macOS E2E.

Технические основания: [Apple NEPacketTunnelProvider](https://developer.apple.com/documentation/networkextension/nepackettunnelprovider), [tun2proxy virtual DNS](https://github.com/tun2proxy/tun2proxy).
