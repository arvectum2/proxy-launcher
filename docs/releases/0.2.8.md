# Arvectum Proxy Launcher 0.2.8

Stable regression-fix release for Windows x64, Astra Linux 1.8 x86-64 and RED OS 8.0.3 x86-64.

## Русский

### Главное

0.2.8 исправляет обнаруженный на физическом RED OS 8.0.3 / KDE Plasma сценарий восстановления сети. Если во время активного Proxy Launcher пользователь частично меняет desktop proxy и KDE возвращает только одно из управляемых полей к исходному значению, rollback больше не застревает в состоянии «НУЖНО ВОССТАНОВИТЬ СЕТЬ».

Проверка остаётся fail-closed: при восстановлении каждое управляемое Arvectum поле должно быть либо исходным сохранённым значением, либо значением, применённым Proxy Launcher. Любое третье/чужое значение по-прежнему запрещает destructive rollback.

Также служебные recovery/capability сообщения теперь используют фактическую подпись платформы. На RED ОС это `Linux / RED OS`, на Astra Linux — `Linux / Astra Linux`; пользовательские сообщения RED ОС больше не содержат статического `Linux/Astra`.

## English

### Highlights

0.2.8 fixes a network-recovery regression reproduced on physical RED OS 8.0.3 / KDE Plasma. If the desktop proxy is partially changed while Proxy Launcher is active and KDE restores only one governed field to its saved value, rollback no longer becomes stranded in a recovery-required loop.

Recovery remains fail-closed: each Arvectum-governed field must equal either its saved original value or the value applied by Proxy Launcher. Any third/foreign value still blocks destructive rollback.

Recovery and capability messages now use the detected platform label. RED OS shows `Linux / RED OS`, Astra Linux shows `Linux / Astra Linux`, and RED OS no longer exposes stale user-facing `Linux/Astra` wording.
