# Arvectum Proxy Launcher 0.2.7

Stable cross-platform release for Windows x64, Astra Linux 1.8 x86-64 and RED OS 8.0.3 x86-64.

## Русский

### Главное

0.2.7 добавляет RED ОС как отдельную проверенную Linux-платформу, не маскируя её под Astra Linux. На RED ОС интерфейс теперь показывает `Linux / RED OS`; Astra Linux сохраняет `Linux / Astra Linux`.

Физический acceptance выполнен на RED OS 8.0.3 Standard Desktop x86_64 / KDE Plasma X11. Проверены установка RPM, GUI-запуск, NetworkManager + KDE system PAC, Chromium в режиме системного прокси, localhost/no-proxy, emergency rollback, autostart, diagnostics, полное удаление и чистая повторная установка с точным восстановлением исходного состояния сети.

### Публичные пакеты

- `Arvectum-Proxy-Launcher-0.2.7-windows-x64-setup.exe`
- `Arvectum-Proxy-Launcher-0.2.7-windows-x64-portable.zip`
- `Arvectum-Proxy-Launcher-0.2.7-astra-linux-amd64.deb`
- `Arvectum-Proxy-Launcher-0.2.7-redos-linux-x86_64.rpm`
- `SHA256SUMS.txt`

### RED ОС

Установка с правами администратора:

```bash
dnf install ./Arvectum-Proxy-Launcher-0.2.7-redos-linux-x86_64.rpm
```
После установки приложение доступно из системного меню как `Arvectum Proxy Launcher`. На физическом acceptance-стенде дополнительно создаётся пользовательский ярлык на рабочем столе из канонического system desktop entry.

RPM не выполняет привилегированные сетевые изменения в package lifecycle hooks: изменение системного прокси остаётся явным пользовательским действием через NetworkManager/PolicyKit и KDE desktop settings plane.

### Astra Linux

DEB остаётся отдельным пакетом для Astra Linux 1.8/Fly и Debian-family окружений. Исправленный в 0.2.6 путь Firefox `Use system proxy settings` через NetworkManager + desktop GSettings сохраняется.

### Windows

Windows portable и Setup пересобираются из того же release commit. Контракт WinINET PAC/rollback и installer lifecycle остаётся покрыт CI. 0.2.7 не заявляет Microsoft Authenticode-подпись.

### GitVerse

GitHub остаётся каноническим источником release bytes. GitVerse независимо зеркалирует тот же набор. Неподдерживаемые GitVerse расширения (`.exe`, `.deb`, `.rpm`) перевозятся в детерминированных однофайловых ZIP-обёртках; после публикации workflow повторно скачивает assets и проверяет SHA-256 исходных payload.

## English

### Highlights

0.2.7 promotes RED OS as a separately verified Linux target instead of presenting it as Astra Linux. RED OS now shows the product signature `Linux / RED OS`; Astra Linux continues to show `Linux / Astra Linux`.

Physical acceptance was completed on RED OS 8.0.3 Standard Desktop x86_64 / KDE Plasma X11, covering RPM installation, GUI startup, NetworkManager + KDE system PAC, Chromium system-proxy mode, localhost/no-proxy, emergency rollback, autostart, diagnostics, full removal, clean reinstall, and exact restoration of the pre-existing network state.

### Public packages

- `Arvectum-Proxy-Launcher-0.2.7-windows-x64-setup.exe`
- `Arvectum-Proxy-Launcher-0.2.7-windows-x64-portable.zip`
- `Arvectum-Proxy-Launcher-0.2.7-astra-linux-amd64.deb`
- `Arvectum-Proxy-Launcher-0.2.7-redos-linux-x86_64.rpm`
- `SHA256SUMS.txt`

### RED OS

Install with administrator rights:

```bash
dnf install ./Arvectum-Proxy-Launcher-0.2.7-redos-linux-x86_64.rpm
```

The package installs the canonical application/menu desktop entry without privileged package lifecycle network hooks. Proxy mutation remains an explicit user action through NetworkManager/PolicyKit and the KDE desktop settings plane.

### Astra Linux

The DEB remains the dedicated Astra Linux 1.8/Fly package. The Firefox system-proxy fix introduced in 0.2.6 remains in place through NetworkManager + desktop GSettings publication.

### Windows

Windows portable and Setup are rebuilt from the same release commit. WinINET PAC/rollback and installer lifecycle contracts remain CI-gated. Release 0.2.7 does not claim Microsoft Authenticode signing.

### GitVerse

GitHub remains the canonical release-byte source. GitVerse independently mirrors the same release set. Unsupported extensions (`.exe`, `.deb`, `.rpm`) are transported as deterministic single-file ZIP wrappers, and the mirror workflow re-downloads every asset and verifies each canonical payload SHA-256.
