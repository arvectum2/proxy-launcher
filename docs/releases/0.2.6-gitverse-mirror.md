# Arvectum Proxy Launcher 0.2.6 — GitVerse mirror

GitHub is the canonical release-byte source for `v0.2.6`. GitVerse provides an independently retrievable Russian mirror of the same canonical payloads.

## Transport rule

GitVerse accepts only a bounded set of release-asset extensions. Canonical files whose extensions are accepted are mirrored directly. Unsupported extensions are placed in deterministic **single-file ZIP wrappers** without changing the original payload bytes.

For `v0.2.6` this means:

| Canonical GitHub payload | GitVerse transport |
| --- | --- |
| `Arvectum-Proxy-Launcher-0.2.6-windows-x64-portable.zip` | direct ZIP |
| `Arvectum-Proxy-Launcher-0.2.6-windows-x64-setup.exe` | `...setup.exe.zip` single-file wrapper |
| `Arvectum-Proxy-Launcher-0.2.6-astra-linux-amd64.deb` | `...deb.zip` single-file wrapper |
| `SHA256SUMS.txt` | direct text file |

The generic mirror workflow fails closed if an existing GitVerse asset with an expected name has different bytes. It does not overwrite an immutable published asset. After upload, every asset is downloaded again and the canonical inner payload SHA-256 is verified.

## Astra installation from GitVerse

1. Download `Arvectum-Proxy-Launcher-0.2.6-astra-linux-amd64.deb.zip` from the GitVerse `v0.2.6` release.
2. Extract it once; the archive contains exactly one file, `Arvectum-Proxy-Launcher-0.2.6-astra-linux-amd64.deb`.
3. Verify the extracted DEB against the `SHA256SUMS.txt` value from the canonical release.
4. Install with `sudo apt install ./Arvectum-Proxy-Launcher-0.2.6-astra-linux-amd64.deb`.

## Verification contract

The mirror is accepted only when:
- release tag/title/body match the GitHub release;
- the GitVerse asset-name set exactly matches the deterministic transport map;
- direct assets match canonical SHA-256;
- each wrapper contains exactly one correctly named original file;
- every extracted payload matches the canonical GitHub SHA-256.
