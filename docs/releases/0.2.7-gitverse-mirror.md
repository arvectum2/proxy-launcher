# Arvectum Proxy Launcher 0.2.7 — GitVerse mirror

GitHub is the canonical release-byte source for `v0.2.7`. GitVerse provides an independently retrievable mirror of the same canonical payloads.

## Transport map

| Canonical GitHub payload | GitVerse transport |
| --- | --- |
| `Arvectum-Proxy-Launcher-0.2.7-windows-x64-portable.zip` | direct ZIP |
| `Arvectum-Proxy-Launcher-0.2.7-windows-x64-setup.exe` | `...setup.exe.zip` single-file wrapper |
| `Arvectum-Proxy-Launcher-0.2.7-astra-linux-amd64.deb` | `...deb.zip` single-file wrapper |
| `Arvectum-Proxy-Launcher-0.2.7-redos-linux-x86_64.rpm` | `...rpm.zip` single-file wrapper |
| `SHA256SUMS.txt` | direct text file |

The generic mirror fails closed if an existing asset under an expected name has different bytes. It never overwrites a published immutable asset. Every mirrored asset is downloaded again; wrappers must contain exactly one canonical file with its original name, and the inner payload SHA-256 must match the GitHub release manifest.

## RED OS installation from GitVerse

1. Download `Arvectum-Proxy-Launcher-0.2.7-redos-linux-x86_64.rpm.zip` from the GitVerse `v0.2.7` release.
2. Extract it once; the archive contains exactly `Arvectum-Proxy-Launcher-0.2.7-redos-linux-x86_64.rpm`.
3. Verify the RPM against `SHA256SUMS.txt`.
4. Install the RPM with administrator rights using the system package manager.

## Verification contract

The mirror is accepted only when release metadata matches GitHub, the asset-name set exactly matches the deterministic transport map, direct assets match canonical SHA-256 values, wrappers contain exactly one correctly named original file, and every extracted payload matches the canonical GitHub SHA-256.
