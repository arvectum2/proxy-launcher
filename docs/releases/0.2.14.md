# Arvectum Proxy Launcher 0.2.14

Patch release focused on macOS sleep/wake recovery and Safari/CFNetwork proxy-policy stability.

The published v0.2.13 release, tag, and assets remain immutable. 0.2.14 is a new release.

## Русский

### Что изменилось

- **Safari после сна снова работает через APL:** устранён физически воспроизводившийся сценарий, когда после sleep/wake Safari сохранял устаревшее состояние CFNetwork и начинал обходить включённый HTTP/HTTPS proxy напрямую по IPv6.
- **Безопасное восстановление proxy-policy:** после длинной паузы worker APL определяет разрыв heartbeat, ждёт короткую стабилизацию сети и выполняет ownership-verified refresh. Для реального SystemConfiguration change APL временно меняет только порядок тех же bypass-доменов и сразу возвращает исходный порядок. Набор и количество исключений не меняются.
- **Без окна прямого трафика:** recovery не выключает HTTP/HTTPS proxy, не включает 48-й bypass-домен, не меняет PAC/SOCKS и не перезапускает Safari/WebKit.
- **Кнопка «Выключить прокси» после wake доступна:** wake guard больше не блокирует безопасный Off; отложенное macOS-подтверждение с default=No сохранено.
- **GUI lifecycle watchdog:** если Tk callback потерян после sleep/wake, интерфейс сверяется с фактическим backend-state и снимает зависшее busy-состояние без сетевых мутаций.
- **macOS packaging CI:** изменения proxy_gui.py и соответствующих тестов теперь участвуют в триггере macOS package workflow.
- **Проверено физически на Apple Silicon:** реальный sleep/wake 24 сентября 2026 г. вызвал recovery (gap=64.699s, refreshed=true); уже открытая страница Safari успешно перезагрузилась при всё ещё включённом APL, без Off и без перезапуска браузера.
- **Rollback сохранён:** synthetic pause и обычный Off подтвердили точное восстановление исходной Wi-Fi proxy-конфигурации.

## English

### Changes

- **Safari survives sleep/wake through APL:** fixed the physically reproduced case where Safari retained stale CFNetwork proxy-policy state after sleep/wake and started bypassing the enabled HTTP/HTTPS proxy directly over IPv6.
- **Safe proxy-policy recovery:** after a long worker heartbeat gap APL waits briefly for network stabilization and performs an ownership-verified refresh. To force a real SystemConfiguration change, it rotates only the order of the same bypass domains and immediately restores the exact original order. The bypass set and count never change.
- **No direct-traffic window:** recovery never disables HTTP/HTTPS proxy, never introduces a 48th bypass domain, does not change PAC/SOCKS, and does not restart Safari/WebKit.
- **Off remains available after wake:** the wake guard no longer blocks the safe Off action; deferred macOS confirmation with default=No remains in place.
- **GUI lifecycle watchdog:** if a Tk callback is lost after sleep/wake, the UI reconciles against the real backend state and clears stale busy state without mutating network configuration.
- **macOS packaging CI:** proxy_gui.py and its regression tests now trigger the macOS packaging workflow.
- **Apple Silicon physical acceptance:** on 24 September 2026 a real sleep/wake produced recovery (gap=64.699s, refreshed=true); the already-open Safari page then reloaded successfully while APL remained enabled, with no Off and no browser restart.
- **Rollback preserved:** synthetic pause testing and normal Off both restored the exact pre-APL Wi-Fi proxy baseline.
