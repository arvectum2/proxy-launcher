# Arvectum Proxy Launcher 0.2.9

Stable rollback-safety release for Windows x64, Astra Linux 1.8 x86-64 and RED OS 8.0.3 x86-64.

## Русский

### Главное

0.2.9 устраняет Windows-асимметрию, найденную при сравнении rollback/recovery с Astra Linux и RED ОС. Если пользователь или администратор меняет системный прокси, пока Proxy Launcher активен, Windows-версия больше не должна молча перезаписывать более новое чужое состояние сохранённым baseline.

Перед destructive rollback теперь проверяется каждое управляемое значение WinINET и пользовательского proxy environment. Допустимы только два доказуемых состояния: сохранённое исходное значение или значение, применённое Arvectum. Любое третье значение считается внешним/чужим, restore завершается fail-closed, а rollback evidence сохраняется для безопасного повторного разрешения.

Обычный сценарий, когда пользователь вручную выключил Arvectum PAC и вернул поле к сохранённому исходному состоянию, остаётся recoverable. Recovery-autostart теперь снимается только после фактического закрытия и WinINET-, и environment-backup.

Linux-поведение из 0.2.8 сохраняется без изменений: Astra/Fly (GSettings) и RED ОС/KDE используют тот же saved-or-Arvectum принцип и защищают третье/чужое состояние.

## English

### Highlights

0.2.9 removes a Windows rollback asymmetry found while comparing recovery semantics with Astra Linux and RED OS. If a user or administrator changes the system proxy while Proxy Launcher is active, the Windows build no longer silently overwrites newer foreign state with the saved baseline.

Before destructive rollback, every governed WinINET and per-user proxy-environment value is validated. Only two proven states are accepted: the saved original value or the value applied by Arvectum. Any third value is treated as foreign; restore fails closed and durable rollback evidence is retained for safe retry or resolution.

The normal case where a user manually disables the Arvectum PAC by returning a field to its saved original state remains recoverable. Recovery autostart is removed only after both WinINET and environment rollback evidence are actually cleared.

Linux behavior from 0.2.8 is retained unchanged: Astra/Fly (GSettings) and RED OS/KDE follow the same saved-or-Arvectum principle and preserve third-party state.
