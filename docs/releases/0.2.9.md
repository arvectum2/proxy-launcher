# Arvectum Proxy Launcher 0.2.9

Stable Windows proxy-ownership hardening release for Windows x64, Astra Linux 1.8 x86-64 and RED OS 8.0.3 x86-64.

## Русский

### Главное

0.2.9 устраняет асимметрию Windows rollback, обнаруженную после исправления RED ОС в 0.2.8. Пока Proxy Launcher активен, пользователь или администратор может изменить системный WinINET proxy/PAC или пользовательские `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY`. Теперь перед восстановлением Windows-версия атомарно проверяет все управляемые поля: каждое должно быть либо сохранённым исходным значением, либо значением, применённым Arvectum.

Обычный mixed-state остаётся восстанавливаемым: например, если пользователь вручную выключил Arvectum PAC, а другие управляемые поля ещё содержат значения launcher, обычное выключение безопасно возвращает исходный baseline. Если же появляется третье/чужое значение — например корпоративный PAC или новый manual proxy — rollback выполняется fail-closed, не меняет WinINET и proxy environment и сохраняет evidence для безопасного повторного восстановления.

Это приводит Windows к той же ownership-семантике, которая используется Linux backend для Astra Linux и RED ОС.

## English

### Highlights

0.2.9 removes a Windows rollback asymmetry identified after the RED OS recovery fix in 0.2.8. While Proxy Launcher is active, a user or administrator may change WinINET proxy/PAC state or the per-user `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY` environment. Windows now performs an atomic ownership preflight before restoration: every governed field must equal either the saved original value or the value applied by Arvectum.

Ordinary mixed state remains recoverable. For example, if the user manually disables the Arvectum PAC while other governed fields still contain launcher-applied values, normal stop safely restores the saved baseline. A third/foreign value, such as a corporate PAC or new manual proxy, fails closed: WinINET and proxy environment are not mutated and rollback evidence is retained for a safe retry.

This aligns Windows with the ownership semantics already used by the Linux backend for Astra Linux and RED OS.
