# Arvectum Proxy Launcher 0.2.9

Stable recovery-safety release for Windows x64, Astra Linux 1.8 x86-64 and RED OS 8.0.3 x86-64.

## Русский

### Главное

0.2.9 закрывает обнаруженную при сравнении платформ асимметрию Windows rollback. До этого при наличии валидного backup Windows мог без проверки текущего состояния восстановить старый WinINET/proxy-environment snapshot и тем самым перезаписать более новое proxy-изменение пользователя или администратора.

Теперь перед любой rollback-мутацией Windows проверяются обе управляемые поверхности — WinINET и пользовательские `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY`. Каждое поле должно быть либо сохранённым исходным значением, либо значением, установленным Arvectum. Mixed-state из этих двух допустимых состояний восстанавливается; любое третье/чужое значение блокирует destructive rollback до изменения каких-либо полей.

Это делает Windows recovery семантически симметричным Astra Linux / RED OS: ручное отключение Arvectum PAC остаётся восстанавливаемым, а новый корпоративный PAC, manual proxy или proxy-env, заданный после запуска приложения, не должен молча перетираться.

Linux-пути 0.2.8 сохраняются без функциональных изменений: Astra/Fly использует NetworkManager + GSettings, RED OS/KDE — NetworkManager + KDE PAC integration.

## English

### Highlights

0.2.9 closes a Windows rollback asymmetry found during cross-platform recovery review. Previously, a valid Windows backup could be replayed without validating the current WinINET/proxy-environment state, potentially overwriting a newer proxy change made by the user or an administrator.

Windows now preflights both governed surfaces — WinINET and the per-user `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY` environment — before any rollback mutation. Every field must equal either its saved baseline or the value applied by Arvectum. Mixed states composed only of those two values remain recoverable; any third/foreign value blocks destructive rollback before any field is changed.

This aligns Windows recovery semantics with Astra Linux / RED OS: manually disabling the Arvectum PAC remains recoverable, while a newer corporate PAC, manual proxy or proxy environment change is preserved rather than silently overwritten.

The Linux paths introduced through 0.2.8 remain functionally unchanged: Astra/Fly uses NetworkManager + GSettings and RED OS/KDE uses NetworkManager + KDE PAC integration.
