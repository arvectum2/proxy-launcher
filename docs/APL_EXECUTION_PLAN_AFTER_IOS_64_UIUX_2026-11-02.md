### Smart Exclusions — обновление 02.11 после практического TCP-теста

**Следующая итерация:** [experimental per-flow intent patch и Apple TN3120 feasibility gate](APL_SMART_FLOW_PER_CONNECTION_ADR_2026-11-02.md): cross-compiled host policy, production DIRECT не активирован; platform gate остаётся blocked.


**`APL-SMART-SHAREDIP-GUARD-020` реализован:** выявленные IP-конфликты с pending/rejected доменами теперь fail-closed; Swift 113/113, Python 8/8, iOS Simulator BUILD PASS, реальный localhost TCP/HTTP/proxy стенд доказал прежний shared-IP leak и отказ от DIRECT при известной коллизии. [Детальная приёмка и IP/HTTPS evidence](APL_IOS_SMART_EXCLUSIONS_SHARED_IP_GUARD_2026-11-02.md). **`APL-SMART-FLOW-001` остаётся обязательным blocker для полной гарантии**: неизвестные имена на общем IP нельзя исключить средствами Network Extension `excludedRoutes`, нужен защищённый domain-aware per-flow engine + физический iPhone E2E, безопасная маршрутизация UDP/IPv6/DNS и управляемая сеть. Не отмечать всю Smart Exclusions 2.0 как DONE.

## 4. Очерёдность и конкретные ближайшие действия

**Очередь A — можно начать немедленно, без решений Apple:**

1. `APL-IOS-UPGRADE-020` — получить именно 0.1.41 release baseline и подготовить изолированную матрицу миграции с проверкой Keychain/профилей/исключений, с безопасными негативными случаями.
2. `APL-I18N-NATIVE-QA-020` — сформировать экспорт важнейших строк для независимых редакторов и список дефектов/критериев приёмки; модель не выступает «носителем», редакторы реально должны подтвердить результат.
3. `APL-SMART-EXCL-020` — закрыть ограниченную безопасную 0.2.0-возможность и документировать IP-vs-domain limitations; **не** внедрять нестабильный per-flow packet engine незадолго до релиза.
4. Параллельные автономные исследовательские дорожки: `APL-PROX-001` и `APL-QRG-001` (spec/ADR/тестовый план). Их окончание не блокирует готовый 0.2.0.

**Очередь B — после результатов A / решения владельца:** релизный freeze iOS, exact-head CI, выпуск новой Distribution IPA (последняя `.ipa` с прежними 50/53 локализациями считается устаревшей), read-only Apple Account/Review check, отдельно — согласованное действие в App Store Connect. В рамках macOS/Android — только независимые от iOS гейты своих магазинов.

**Очередь C — следующая версия после 0.2.0:** Proxifier-like shared rules + reuse Windows WinDivert и feasibility macOS/Linux; изолированный QRVPN-like Gateway; DNS/per-flow Smart Exclusions R&D; 175 storefronts; iCloud по решению владельца. Не перегружать релиз iOS 0.2.0 инфраструктурой серверов и системными драйверами.

## 5. Decision gates и правила сохранения существующего продукта

- **Не трогать** заявку iOS 0.1.41, пока Apple рассматривает её; не считать статус «approved» без свежего read-only подтверждения. Публикация 0.2.0, её загрузка/merge, принятие новых Apple agreements, изменение доступности стран — отдельные owner-authorized операции.
- **Сохранить** два действующих формата рекламы РСЯ и принятые пользователем сведения App Store о конфиденциальности; менять их лишь по новой фактической необходимости и отдельному решению. Никаких скрытых публикаций, серверных прокси/секретов и действий с личным iPhone для roadmap-аудита.
- Доказанные физические A→B→A, VoiceOver, упакованные 64 UI языка и 50 ASO не перепроверять повторно без изменения сетевого/локализационного кода. Последний симуляторный билд ≠ новый подписанный релизный IPA.
- Релизное расширение Proxifier/QRVPN и правовые требования VPN в РФ/других странах — исследовать отдельно, не обещать абсолютную законность VPN или недоступные OS privileges.
- **Физически непроверенные внешние статусы** (Apple/RuStore live, правовые условия) остаются `requires_read_only_verification`, а не автоматически отмечаются как завершённые.

**Definition of Done этого roadmap-аудита:** достоверные completed/pending границы, актуальные ID/приоритеты, понятный первый следующий технический шаг, ссылки на технические планы, сохранение исторического следа, документационная правка без изменения кода или действий во внешних сервисах.
