# Smart Routing 4.0 — независимые TCP-свидетельства лабораторного маршрута

Дата: 05.11.2026. Задача: `APL-IOS-SMART4-EGRESS-WITNESS-20261105`.

## Назначение и граница доказательств

`Smart4DryRunAudit` до этого принимал `confirmedDirect/confirmedViaProxy` как входные значения. DNS-ответ, известный IP, клиентский `connect()` и такой enum **не доказывают реальный egress**. Новый `scripts/qa_smart4_egress_witness.py` получает **положительное серверное подтверждение TCP-пробы** от отдельного наблюдателя и проверяет соответствие заранее объявленному решению Smart4. Отсутствие записи никогда не считается подтверждением другого пути.

Новый сборщик НЕ импортируется в iOS и не подключён к PacketTunnel, NetworkExtension, Keychain, аналитике или приложению. Он не меняет VPN/DNS/маршруты, не пересылает TCP, не загружает сайты, не читает профили. Он принимает только синтетические QA-пробы. Запись — исключительно в отдельный новый файл для каждой стороны (POSIX mode 0600, без перезаписи). На Windows слушатели запрещены, поскольку `os.open(mode=0600)` не гарантирует приватные POSIX-права; автономный offline verifier работает.

Это **подготовка аппаратной приёмки 2b.2, а НЕ пройденная аттестация физического iPhone**. До теста на отдельном устройстве, с подтверждённым PacketTunnel-контекстом и независимыми внешними наблюдателями, `physical_egress_verified` всегда `false`, даже если локальная лаборатория зелёная. Apple-supported DIRECT, IPv6 DIRECT, QUIC, shared-CDN и Wi-Fi/LTE этим инструментом не доказаны.

## Протокол и ограничения

- Два независимых TCP-наблюдателя `DIRECT` и `PROXY` с отдельными файлами. Каждый сервер принимает строго `APL4/1 ` + 32 строчных hex-символа случайной 128-битной пробы + LF. Клиент получает `APL4/1 OK` после приёма. Произвольный HTTP/payload отвергается без сохранения.
- План (`intents.jsonl`) содержит только `token`, `route` (`DIRECT`/`PROXY`), `issued_at_ms`. Файл каждого наблюдателя содержит только `token` и `received_at_ms`. Ни hostname, ни URL, IP, cookie, логин, пароль, payload, ID устройства или историю туда не записывать.
- Положительное свидетельство должно поступить в пределах 30 секунд после начала пробы; проверка — не позднее 120 секунд от начала/приёма. Повтор, конфликт, устаревание, будущее время, отсутствие подтверждения и IP-only предположение **не засчитываются как совпадение**. Неизвестный токен, лишние поля или неверная JSONL-схема отвергают проверку.
- Максимум 256 проб на файл; чтение каждой JSONL-строки ограничено 300 байт. Сторона слушает максимум 120 секунд и обрабатывает максимум 256 успешных или 512 общих соединений. По умолчанию можно слушать только числовой loopback; с явным `--physical-lab` — только конкретный частный RFC1918 IPv4, без wildcard/публичного адреса.
- Вывод — только суммарные счётчики. `attested` не может быть true без **положительного DIRECT и положительного PROXY**, отсутствия ошибок и неопределённостей; в выводе всегда `scope: synthetic_lab_only` и `physical_egress_verified: false`.

## Запуск на изолированном стенде

```sh
python3 scripts/qa_smart4_egress_witness.py listen --channel DIRECT --bind 127.0.0.1 --port 0 --output /tmp/lab-direct-new.jsonl --duration 60
python3 scripts/qa_smart4_egress_witness.py listen --channel PROXY --bind 127.0.0.1 --port 0 --output /tmp/lab-proxy-new.jsonl --duration 60
python3 scripts/qa_smart4_egress_witness.py verify --intents /tmp/lab-intents-new.jsonl --direct /tmp/lab-direct-new.jsonl --proxy /tmp/lab-proxy-new.jsonl
```

Наблюдатели запускаются **параллельно** на разных портах и автоматически завершаются. Клиент создаёт каждый токен `secrets.token_hex(16)` непосредственно перед TCP-запросом; значение `route` должно происходить из реального результата Swift Smart4 policy, а **не из уже полученного свидетельства**. Текущий CLI проверяет формат и совпадения, но не может криптографически доказать происхождение решения от Swift: подмена input-файлов не является независимой физической аттестацией. Журналы должны создаваться и храниться доверенными серверными наблюдателями стенда.

Для реальной аппаратной проверки DIRECT и PROXY-наблюдатели должны находиться за двумя разными контролируемыми egress-путями. Нужно дополнительно подтвердить интерфейс/источник выхода и то, что **именно захваченный PacketTunnel-поток** доставил токен. Простое отправление запроса из телефона прямо на выбранный порт без туннеля нельзя считать доказательством маршрутизации Smart3/Smart4.
