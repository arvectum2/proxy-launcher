## Stage 6c–6d — mutation epoch and persistent encrypted native backup

Each successful v2 catalog publication now mints a fresh opaque `mutationEpoch` UUID, including journal entry, commit, rollback and each retired-record checkpoint. The publishing helper returns the actual persisted snapshot via `inout` only after successful storage replacement, so comparisons and exact journal rollback use the new epoch, not pre-publication metadata. v1/v2 without this optional field still decode; older candidate writers must not be mixed with the new writer because they do not preserve or advance it. No schema migration is triggered by reading. It prevents stale review reuse after same-content new-writer ABA transitions and rollback, not cross-process CAS, hostile storage replay or legacy-ID ABA. Existing selection authority remains separate. Updated rollback tests compare all original metadata except the deliberately changed epoch; simulator QA cleanup compares logical emptiness explicitly without treating a written empty catalog as a never-written snapshot. No simulator execution.

The device-gated persistent sheet now supports native encrypted JSON import and export through the existing backup codec and catalog. Import file is bounded to 1 MiB, security-scoped, decrypted after explicit password entry, reviewed by protocol counts, and confirmed through the existing additive journaled restore and fresh VPN-off census. Existing profiles/selection, legacy secrets and retired entries are not overwritten. Export requires a single-use, five-minute snapshot/legacy-bound review, current nonempty unconflicted catalog, both matching passwords, exact credential reads and VPN inactivity checks before and after encryption. Only current native records are sealed; no selection metadata, tickets, retired or legacy profiles. Only ciphertext is handed to the file exporter with a unique receipt-bound filename. No file export starts automatically. File replies preserve their exact import/export receipt; dismissal/background discards pending review/password/file state. Async work checks generation/visibility and foreground before proceeding. Swift String and Data lifetime are not guaranteed secure erasure; actual UI/file-provider behavior, real Keychain and VPN-state races are unverified. No real storage/device/UI activity. Two additional synthetic tests cover same-content ABA and rollback, failed publication not advancing epoch, stale/single-use backup reviews, wrong password, inactive guard, current-only encrypted export and additive restore.
