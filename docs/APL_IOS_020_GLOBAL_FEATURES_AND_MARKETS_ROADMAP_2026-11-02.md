## 2. Что означает «все географии Apple» — два разных каталога

По официальной документации Apple на 02.11.2026 App Store доступен в **175 странах/регионах**, а App Store Connect поддерживает **50 языковых/региональных локализаций метаданных**. 31.03.2026 Apple объявила о расширении на 11 новых языков до 50. Полный охват витрин достигается 50 корректными локализациями плюс документированной fallback-матрицей и, только после отдельного решения, настройкой доступности продукта по территории. **175 независимых переводов не требуется и не существует как 175 вариантов метаданных App Store.**

Официальные источники:
- https://developer.apple.com/help/app-store-connect/reference/app-information/app-store-localizations
- https://developer.apple.com/news/?id=97t4mt64
- https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/manage-availability-for-your-app-on-the-app-store
- https://developer.apple.com/help/app-store-connect/manage-app-information/localize-app-information
- https://developer.apple.com/documentation/appstoreconnectapi/managing-metadata-in-your-app-by-using-locale-shortcodes

### Проверенное фактическое покрытие репозитория (не состояние ASC live)

- `mobile/ios/Resources/*.lproj`: **50 UI-языков**, 5 `.strings` каталогов на каждый: `Localizable` (155), `ProfileManagement` (101), `ProxyImport` (40), `SmartExclusions` (45), `QuickActions` (3). Текущее соотношение — **50 × 344 = 17 200** записей UI; это не сертификат вычитки носителями.
- `mobile/ios/ASO/localizations.json` и `ASO/metadata/`: **47 из 50** разрешённых Apple локализаций, status **`editorial_source_ready_not_uploaded`** (на сервер Apple не передавались в рамках этой задачи). Сейчас подготовлено 47 комплектов локализованных скриншотов по 2 кадра = **94**.
- Сверено с официальными 50 Apple locale shortcodes: **нет ровно 3** — `or-IN` (Odia / ория), `sl-SI` (словенский), `uk` (украинский). Лишних кодов в ASO нет. В UI тоже нет базовых `or`, `sl`, `uk`. **Цель для 0.2.0: 53 UI-языка, 50/50 Apple ASO-вариантов, не менее 100 исходных скриншотов.**
- Уже есть важные для других аудиторий UI-локализации, не выделяемые Apple в отдельную витрину ASO: например `am`, `ha`, `fa`, `fil`, `sw`, `uz`, `sr`, `bg`. Их **не удалять** ради механического равенства 50/50; применяются Apple fallback и региональные правила.
- Региональные варианты Apple (например `en-US/en-GB/en-AU/en-CA`, `fr-FR/fr-CA`, `es-ES/es-MX`, `pt-BR/pt-PT`) уже представлены в ASO; они **не требуют автоматически** отдельного `.lproj` для каждого варианта интерфейса, пока нет существенных региональных отличий UI. Для норвежского iOS `nb` соответствует Apple metadata `no` — mapping проверять явно.

### APL-I18N-050 — выполнение, 0.2.0 / P0

1. **UI**: добавить три полных `Resources/{or,sl,uk}.lproj` (все пять каталогов и **344 ключа в каждом**, всего +1 032 строки), `AppLanguage`, языковые имена и системный fallback. Не использовать английский текст как фиктивный перевод, кроме явного fallback при отсутствии системной поддержки. Сохранить плейсхолдеры `%@/%d`, порядковые аргументы, `host:port`, `SOCKS5`, `VPN`, `DNS` и HTTP-семантику.
2. **Контент и редактура**: перевод интерфейса, подключение/отключение, ошибки, критические действия удаления, исключения сайтов, таймауты, конфиденциальность; контроль качества самостоятельной редактурой + независимая проверка важных терминов/обратным переводом. Не заявлять проверку носителями, если её не было. Поддержать текст без обрезки на iPhone SE, Dynamic Type XXL, VoiceOver; направление письма учитывать для арабского/иврита/урду в полной матрице регрессии.
3. **ASO**: создать строго 3 новых комплекта `ASO/metadata/{or-IN,sl-SI,uk}/` (name, subtitle, description, keywords, promo, what's new, URLs) и `ASO/screenshots/` по два реальных снимка iPhone на локаль. Перегенерировать `ASO/localizations.json` (`supportedLocaleCount=50`) через текущий офлайн builder. Никаких «автозаливок» в текущую карточку 0.1.41.
4. **Автоматизация матрицы**: правило `Apple official 50 − prepared ASO = ∅`, все каталоги и скриншоты присутствуют, UI lang registry согласован с `.lproj` (ожидаем 53), build включает все 53, в ASO ровно 50 корректных Apple-локалей без лишних. Заменить устаревшие тестовые константы 47/50/94/250 на новые обоснованные 50/53/100/265, сохраняя исторические отчёты неизменными. `plutil -lint`, JSON schema, UTF-8 byte limits, placeholders, 0 пустых строк, l10n CI, RTL, 53-локальный screenshot/layout smoke, адресный XCUITest для новых 3 и 2 различных размеров экранов.
5. **Приёмка**: `53/53` UI языков × 5 `.strings` = **265 файлов**, `50/50` Apple ASO метаданных, 2 × 50 = **100** исходных скриншотов, матрица RU/EN/3 новых и RTL без критичных UX-ошибок; ASO импорт лишь после проверки официального release состояния 0.1.41 и отдельного разрешения владельца.

### APL-I18N-MARKETS-175 — география/регионы, P2

1. На основе официальной таблицы Apple завести `storefront → default/alternative ASO locale → UI fallback → availability/status → legal/payment/ads restrictions` для всех текущих 175 территорий. Проверять срез Apple периодически; каталоги меняются.
2. Выделить автономный **country audit**: где App Store реально разрешает продукт к распространению, какие правовые ограничения для VPN/шифрования/рекламы применимы, где РСЯ не показывает объявления, какие языки нужны для Support/FAQ. Не ставить галочку «доступно» без read-only подтверждения аккаунта.
3. Отдельная следующая волна iOS UI языков **вне списка 50 метаданных** по проверенной поддержке платформой и рынку: определить приоритет и код BCP 47 только после matrix-аудита, без обязательства переводить «по одному языку на страну». Вести матрицу `нет UI`/`только ASO fallback`/`UI локализован`/`editorial QA`/`опубликован`. Не переносить тексты 0.2.0 автоматически в Android/macOS: общий реестр `localization/apl-locales.json` сейчас не покрывает все iOS языки; согласование делается отдельной задачей с тестами.

## 3. Proxifier → собственный механизм APL (без копирования закрытого кода)

Сопоставление только с публичным контрактом и легитимными black-box тестами; **не ставить целью декомпиляцию/копирование чужого закрытого ПО**, обход лицензии, заимствование фирменных ресурсов, названия или приватных сетевых API. Документация продукта: https://www.proxifier.com/features.html и https://www.proxifier.com/docs/win-v4/rules.html.

| Milestone | Результат | Критерий готовности |
|---|---|---|
| `APL-PROX-001` P1 — comparison/clean-room | Матрица: процесс/приложение, домен/IP/порт, wildcard/CIDR/ranges, порядок правил, direct/proxy/block, DNS local/remote/hybrid, резервирование/цепочки, failover, журналы и граф соединений, профили импорта/экспорта; по каждой возможности APL macOS/Windows/Linux/Android/iOS отмечены `implemented / partial / blocked / not planned`. | Подтверждено публичными docs и адресными тестовыми сценариями, не обещана полная паритетность на iOS |
| `APL-PROX-002` P1 — routing engine | Независимая от GUI **типизированная модель правил**: priority, match process/bundle-id where OS permits, hostname/SNI/IP/port, direct/deny/proxy/profile/chain, приоритет исключений и default, конфликты и аудит. | Тесты precedence, overlap, IPv4/IPv6, split DNS, loopback, отказоустойчивости и rollback; существующие пользовательские профили/исключения сохраняются |
| `APL-PROX-003` P1/P2 — per-app enforcement | Исследовать и внедрить процессную маршрутизацию на **Windows/macOS/Linux** через поддерживаемые OS network APIs/драйверы только при соответствующих разрешениях; продуктовый PoC на 2 приложениях: одно direct, другое via proxy, одновременно. На iOS — отдельно выяснить реальные ограничения NetworkExtension / managed entitlements; **не обещать глобальное стороннее per-app управление**. | Packet captures + независимый внешний IP/DNS proof для обеих веток, без системных утечек и без поломки существующих подключений |
| `APL-PROX-004` P2 — chains/redundancy | Последовательные/резервные цепочки SOCKS5/HTTP(S), ограничения аутентификации, оповещения, счётчики подключений и базовая аналитика; возможность отключить каждую цепочку/правило. | Failover и backoff при локальном TCP отказе, тест с 2 хопами, IP/DNS-результат подтверждён, пароль не попадает в логи |
| `APL-PROX-005` P2 — безопасный импорт правил | Свой открытый и документированный формат профиля APL; совместимость с чужим форматом (`.ppx`) **только после юридического и технического подтверждения**, без прямого чтения чужих секретов по умолчанию. | Round-trip/миграции, отсутствие потери Keychain и пользовательского выбора |

**Граница 0.2.0**: можно немедленно делать `APL-PROX-001/002` и точечное улучшение существующих Smart Exclusions; не включать в 0.2.0 создание привилегированных драйверов, полное per-app desktop enforcement и платные цепочки без нового scope. Proxifier-подобный функционал должен развиваться как **оригинальный APL routing engine**.

## 4. QRVPN → APL Gateway / Own Server (самостоятельная реализация)

Официальная публичная модель QRVPN: server/client, доступ без обязательного публичного IP или открытых портов, QR/link/file provision, возможен native WireGuard client. **APL не обещает, что может скопировать закрытую relay/NAT архитектуру QRVPN или использовать его серверы.** Исследование — по документации, разрешённому black-box сравнению и собственным открытым протоколам/компонентам. https://www.qrvpn.com/docs/ ; https://www.qrvpn.com/.

| Milestone | Результат | Критерий готовности |
|---|---|---|
| `APL-QRG-001` P1 — исследование/Threat Model | Зафиксировать модель `клиент (APL/iOS или WireGuard) → управляемый APL Gateway → правила direct/proxy → upstream`, аутентификацию пользователей, NAT traversal без публичного IP, допустимые варианты encrypted tunnels, ограничения Apple NetworkExtension и законодательства рынков. | Архитектурная схема, ADR по WireGuard/собственному шлюзу, cost/latency/HA, STRIDE/threat model; не реализовывать неизвестные проприетарные алгоритмы |
| `APL-QRG-002` P1/P2 — собственный gateway PoC | Изолированный сервер (localhost/контролируемая ВМ) с двумя маршрутами direct и upstream-proxy, серверной таблицей исключений и доступом единственного тестового клиента. Независимая конфигурация для пользователей; никаких секретов upstream в выдаваемом клиенту профиле. | Наблюдаемый IP шлюза/выхода (пользователь вправе его узнать), клиент не получает IP:port:login/password upstream в конфиге, журнале, QR или диагностике; fail-closed DNS/leak tests |
| `APL-QRG-003` P2 — защищённая выдача доступов | Одноразовое/короткоживущее приглашение и QR для **клиентского** подключения, токен/ключ с ограничением времени и устройств, отзыв, ротация, аудит без PII. | Создать/подключить/отозвать клиента, отрицательные тесты повторного QR, password-in-URL, компрометации токена и маскировки логов |
| `APL-QRG-004` P2 — серверные правила/группы | Маршруты по доменам/IP/портам и исключения исполняются **на gateway**, per-tenant права и изоляция, первичный+резервный upstream, health-check и повторное соединение. | 2 клиента с различными правилами не влияют друг на друга; отключение upstream переключает только допустимые маршруты; DNS/IP проверки и rollback |
| `APL-QRG-005` P2 — мультиплатформенные клиенты | Для Windows/macOS/Android/iOS реализовать управляемое подключение только через допустимые OS API; проверить совместимость клиента WireGuard как самостоятельный тест, без заявления о гарантии совместимости. | Подключение/отключение/отзыв ключа на 2 OS, отсутствие утечек оригинальных upstream credentials, безопасная повторная установка |
| `APL-QRG-006` P2 — коммерческий/юридический gate | Отдельно определить: self-host vs managed SaaS, лицензирование криптографии/сетевых сервисов и VPN по рынкам, договор/политику хранения/логирования, операционную ответственность, отказоустойчивость, регуляторные требования и условия Apple. | Юридическое заключение по целевым юрисдикциям до публичного SaaS; нагрузочные тесты, rate limit, DoS protection, backup/monitoring, корректный отзыв доступа. Никаких обещаний «легально везде» без проверки |

**Принцип безопасности:** клиент **не видит пароль и настройки закупленного серверного прокси**, но видит адрес сервера и может определить внешний IP; скрыть или сделать неопределяемым реальный IP выхода нельзя обещать. Вложенный VPN в iOS, relay without public IP и конкретные NAT-traversal схемы являются feasibility gates, а не гарантированной функцией.

**Граница релизов:** в 0.2.0 только `APL-QRG-001` и, при готовности изолированного стенда, минимальный **непубличный** `QRG-002` PoC. Публичный сервер, управление клиентами и коммерциализация — отдельная ветка/релиз после security/legal gate; никаких изменений Apple Review 0.1.41, Tailscale Funnel/серверов или production proxy пользователя без отдельного разрешения.

## 5. Порядок исполнения и правила завершения

1. **Сейчас, 0.2.0 / P0:** выполнить `APL-I18N-050`, затем 0.1.41→0.2.0 upgrade/backup/release-контракты и целевой Smart Exclusions QA. Не повторять уже успешную физическую проверку failover/VoiceOver, пока не изменится соответствующий код.
2. **Параллельно как исследование:** `APL-PROX-001`, `APL-QRG-001`. Результат — проверяемая сравнительная матрица и отдельные ADR/spec; публикацию и архитектуру других платформ не связывать с принятой 0.2.0.
3. **После соглашения об интерфейсе правил:** `APL-PROX-002` общая модель правил и совместимость с существующими исключениями; только затем desktop per-app PoC и прокси-цепочки. Серверный QRVPN-like PoC вести отдельно.
4. **Перед релизом 0.2.0:** подписать актуальные исходники, проверить Apple review state 0.1.41 read-only, отдельно согласовать публикацию 0.2.0, ASO и скриншоты; не менять карточку конфиденциальности и не выключать текущую рекламу без отдельного решения владельца.
5. **В дальнейшем:** постепенно проводить `APL-I18N-MARKETS-175` и реализацию Proxifier/QRVPN-like функций, фиксируя только технически/юридически подтверждённую совместимость, а не «полный обратный инжиниринг» в смысле копирования закрытого кода.

**Definition of Done roadmap-этапа:** эти задачи имеют собственные ID, приоритеты, независимый scope, критерии приёмки и понятные продуктовые границы. Разработка новых функций и локализаций по этому документу **ещё не считается выполненной**. Все изменения на этом этапе — только документы и checkpoint.
