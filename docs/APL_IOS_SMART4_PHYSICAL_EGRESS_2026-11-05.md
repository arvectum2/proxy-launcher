# Smart4 — аппаратный стенд и границы проверки (05.11.2026)

Task `APL-IOS-SMART4-PHYSICAL-EGRESS-20261105`; source base main `edfb8932`.

## Исходное состояние и разрешённые изменения

- Владелец разрешил менять VPN-подключение на его iPhone 13, подключённом кабелем к Mac mini, с использованием iPhone Mirroring.
- Физическое устройство iOS 27.2, Developer Mode включён; в APL отображается версия 0.1.41. Изначально VPN был **отключён**, выбран APL как VPN-конфигурация.
- Через Mirroring вручную включили VPN существующего APL, Safari успешно загрузил HTTPS. Независимый внешний IP-ответ при VPN ON был IPv4; после отключения — IPv6. Самих адресов, конфигураций, имён профилей и учётных данных нигде не сохраняли. VPN вручную возвращён в состояние OFF.
- Производственный APL 0.1.41 **не содержит Smart4**, поэтому переключение VPN в нём не доказывает новый per-host PacketTunnel egress.

## Отдельный безопасный QA-клиент (без замены APL)

В собственном bundle `ru.arvectum.qrdeviceqa.device` (ранее применялся для QR hardware QA) к existing QA target добавлена только DEBUG-функция Smart4 physical **transport readiness**. Подписанная Development QA сборка проверена до установки. QA app не имеет NetworkExtension, App Group или Keychain entitlements APL и не читает/сохраняет личные VPN-профили, историю сайтов, IP пользователя или пароли.

Самый важный предел: исходная `SmartFlowRoutingPolicy` из SharedCore вычисляет решения для **двух фиктивных DNS-имён, разделяющих один тестовый IPv4**. После этого сам QA-клиент инициирует на настоящем iPhone два синтетических TCP-потока:

1. `DIRECT` — обычный аппаратный Wi-Fi socket к LAN TCP witness, который положительно отвечает на одноразовый 128-битный token `APL4/1`.
2. `PROXY` — Wi-Fi socket к жёстко ограниченному QA-only HTTP CONNECT посреднику на LAN. Тот принимает только фиксированное `apl-smart4-proxy.invalid:443`, пересылает **только один строго проверенный токен** на `127.0.0.1` ко второму независимому TCP witness; URL, произвольные адреса и личный трафик не проксируются. ACK возвращается лишь после подтверждения второй стороны.

Оба witness (`scripts/qa_smart4_egress_witness.py`) сохраняют только одноразовые токены и метки времени в приватных файлах `0600`. Offline verifier отвергает отсутствие, повтор, конфликт и устаревшие подтверждения. Серверы ограничены по времени и числу потоков, после опыта останавливаются. Данные проб остаются только в локальном приватном каталоге до удаления.

**Важно:** даже успешные два независимых TCP witness доказывают лишь доступность лабораторных DIRECT/CONNECT каналов и вычисление Smart4 модели на устройстве. Они не доказывают, что сам APL `NEPacketTunnelProvider` перевёл захваченный исходный поток через правильный маршрут, и не подтверждают Apple-supported per-host DIRECT. Физический egress оригинального PacketTunnel в Smart4 не доказан. Исходный gate Smart4 2b.2 остаётся `UNVERIFIED`, пока не будет связан оригинальный captured flow из PacketTunnel с внешним получателем.

## Возврат и ограничения

- Не заменять рабочую App Store APL 0.1.41 QA-сборкой и не трогать App Group/Keychain. QA bundle устанавливать отдельно и удалить после проверки.
- В конце сверить VPN=OFF, исходный выбранный VPN-провайдер APL; тестовые TCP-серверы остановить, приватные одноразовые журналы удалить после агрегирования.
- Не подключать Smart4 source-only модель к Release PacketTunnel, не менять параметры Apple 0.2.0 App Review и не включать черновик native FIN PR #314.
